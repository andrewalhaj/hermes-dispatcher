# Honcho Webhook Integration

## Registration

The webhook API (`POST /v3/workspaces/{id}/webhooks`) returns **405 Method Not Allowed** on both cloud and self-hosted. Registration must happen via the Honcho dashboard at [app.honcho.dev](https://app.honcho.dev) → Webhooks page.

Dashboard fields:
- **Endpoint URL** — your receiver (e.g. `https://hermes.andrewskingdom.com/api/hooks/honcho`)
- **Workspace** — the Honcho workspace to bind to
- **Signing Secret** — auto-generated by Honcho (format: `hch-webhook-...`). Not a Bearer token.

There's a **"Send Test"** button that fires a test event to your endpoint — use it to verify.

## Payload Shape

Honcho sends `POST` with `Content-Type: application/json`. The body uses `sort_keys=True` and compact separators `(",", ":")`:

```json
{"data":{"content":"test fact"},"timestamp":"2026-06-24T17:21:33Z","type":"conclusion"}
```

Fields:
- `type` — event type: `conclusion`, `observation`, `session_summary`, or others
- `data` — event-specific payload (shape varies by type)
- `timestamp` — ISO 8601 UTC

The `data` sub-object is what carries the actual content. The `type` field may also appear as `event` in some versions — check both.

## Signature Verification

**Header:** `X-Honcho-Signature`

**Scheme:** HMAC-SHA256 of the raw request body bytes, hex-encoded. The signing key is the webhook's Signing Secret from the dashboard.

Verified from source: [`plastic-labs/honcho/src/webhooks/webhook_delivery.py`](https://github.com/plastic-labs/honcho/blob/main/src/webhooks/webhook_delivery.py):

```python
def _generate_webhook_signature(payload: str) -> str:
    return hmac.new(
        webhook_secret.encode("utf-8"),
        payload.encode("utf-8"),
        hashlib.sha256
    ).hexdigest()
```

And sent as:
```python
headers={"X-Honcho-Signature": signature}
```

### Verification Code (receiver side)

```python
import hmac, hashlib

async def verify_honcho_signature(request, secret: str) -> bytes:
    """Verify X-Honcho-Signature. Returns raw body bytes on success."""
    signature = request.headers.get("X-Honcho-Signature", "")
    if not signature:
        raise HTTPException(401, "Missing X-Honcho-Signature header")

    body = await request.body()
    expected = hmac.new(
        secret.encode("utf-8"),
        body,
        hashlib.sha256,
    ).hexdigest()

    if not hmac.compare_digest(expected, signature):
        raise HTTPException(401, "Invalid signature")

    return body  # parse with json.loads(body)
```

Key points:
- Verify against **raw body bytes**, not a re-serialized JSON object (sort key order, whitespace, and separator differences break re-serialization).
- Use `hmac.compare_digest()` for constant-time comparison.
- The function is `async` because `await request.body()` is async.
- After verification, parse with `json.loads(body)` — don't call `request.json()` (the body is already consumed).

## Common Pitfalls

- **Bear token mismatch:** The signing secret is NOT a Bearer token. Honcho doesn't send `Authorization: Bearer <secret>`. It sends `X-Honcho-Signature: <hex>`. Using Bearer-token comparison is the #1 failure mode.
- **Re-serialization mismatch:** If you `json.loads()` then `json.dumps()` to re-compute the signature, the keys may sort differently or the separators/whitespace may differ from Honcho's `sort_keys=True, separators=(",", ":")` — producing a different hash. Always verify against `request.body()`.
- **Workspace ID mismatch:** The webhook is bound to a specific workspace. If your receiver expects a different workspace's events, it will never fire for those events.
