# ISA Goal Decomposition

> Cherry-picked from [danielmiessler/Personal_AI_Infrastructure](https://github.com/danielmiessler/Personal_AI_Infrastructure) (MIT) on 2026-06-05.
> The *pattern* was absorbed into Hermes' `writing-plans` skill — the upstream
> artifact itself was NOT installed (total overlap with existing skill/memory stack,
> env-incompatible with Hermes).

## The pattern

Define an Ideal State Artifact (ISA) — a spec for what success looks like on a task,
decomposed into Ideal State Criteria (ISC): specific, verifiable pass/fail conditions.
Iterate until all ISCs pass. This turns "did it work?" from an implicit judgment into
an explicit checklist, enabling the LEARN phase to capture which criteria failed and why.

## Hermes mapping

- ISA (Ideal State Artifact) → the plan generated by `writing-plans`
- ISCs (verifiable criteria) → numbered verification items at the plan's end
- "Hill-climb until all ISC pass" → `verification-before-completion` loop — verify
  each criterion, flag failures, fix, re-verify
- LEARN phase → record failures in the plan's post-mortem; feed patterns into
  `knowledge-store` and skill patches

## When to use

- ✅ Multi-step infrastructure tasks (Manifest routing, service daemonization, migrations)
- ✅ Home Assistant automation design — define the target behavior as ISCs, verify each
- ✅ Config changes with non-obvious correctness criteria
- ❌ Single-command tasks (one curl, one file read) — overhead > benefit
- ❌ Purely mechanical work with no judgment call

## Caveats / dependencies

- `writing-plans` + `verification-before-completion` must both be loaded for full loop
- The ISC list must be genuinely verifiable — "works correctly" is not an ISC; "curl
  returns 200 with body containing 'active'" is
- This adds ~2-3 turns to a task (plan → verify → fix → re-verify); budget accordingly
